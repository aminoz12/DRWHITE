Élevé 01

Images produits de la home en basse qualité

Les vignettes best-sellers sont des photos WhatsApp (~578×432). Il faut des rendus pro homogènes, optimisés via next/image.
1 · Remplacer <img> par next/image (optimisation auto)
jsx 
import Image from "next/image";

<div className="product-thumb">   // ratio fixe → zéro CLS
  <Image
    src={product.image}          // rendu pro 1000×1000, fond homogène
    alt={product.name}
    width={600} height={600}
    sizes="(max-width:600px) 45vw, 300px"
    quality={82}
  />
</div>
2 · Cadrage identique pour toutes les vignettes (CSS)
css 
.product-thumb{
  aspect-ratio:1/1;      /* toutes carrées, alignées */
  background:#f4f3fa;    /* même fond partout */
  border-radius:14px; overflow:hidden;
  display:flex; align-items:center; justify-content:center;
}
.product-thumb img{ width:100%; height:100%; object-fit:contain; }
💡 Pourquoi : la home est ta page la plus vue. Des visuels amateurs = perception « dropshipping ». Des rendus homogènes + next/image (WebP/AVIF automatique) crédibilisent la marque ET accélèrent le chargement.
📸 Action non-code : refaire/récupérer les 5 rendus produits en 1000×1000 px, même angle, même fond, mêmes ombres. Réutilise les visuels déjà propres des fiches produit.
Élevé 02

Redirection www → non-www (contenu dupliqué)

Le site répond sur www et non-www ; canonical + sitemap pointent vers non-www. Il faut forcer une seule version en 301.
1 · Redirection permanente dans next.config.js
js 
// next.config.js — force cliniwhite.com (sans www)
module.exports = {
  async redirects() {
    return [{
      source: "/:path*",
      has: [{ type: "host", value: "www.cliniwhite.com" }],
      destination: "https://cliniwhite.com/:path*",
      permanent: true,   // 301
    }];
  },
};
2 · Vérifier la balise canonical (déjà correcte)
jsx 
// app/layout.js ou head — hôte canonique unique
<link rel="canonical" href="https://cliniwhite.com" />
// ✓ ton canonical, sitemap et robots pointent déjà vers non-www :
//   il ne manque QUE la redirection 301 ci-dessus.
💡 Pourquoi : si www et non-www renvoient tous deux un 200, Google voit deux sites identiques et dilue ton référencement. Une 301 concentre toute l'autorité SEO sur une seule URL.
🔧 Sur Vercel/Netlify, tu peux aussi définir le domaine principal dans le dashboard (Domains → « Redirect to primary ») — même effet sans toucher au code.

Élevé 04

Scarcité honnête (« ALMOST SOLD OUT »)

Si le badge s'affiche en permanence sur tous les produits, c'est une fausse urgence — risque de confiance et de conformité.
Afficher le badge uniquement si le stock réel est bas
jsx 
const LOW_STOCK_THRESHOLD = 15;

function StockBadge({ stock }) {
  if (stock === 0)  return <span className="badge out">Out of stock</span>;
  if (stock <= LOW_STOCK_THRESHOLD)
    return <span className="badge low">Only {stock} left</span>; // vrai chiffre
  return null;  // stock normal → aucun badge
}
💡 Pourquoi : une urgence honnête (« Only 8 left », piloté par l'inventaire) convertit sans risque. Une urgence permanente et fausse finit par être repérée et peut être sanctionnée (publicité trompeuse).
✅ Alternative honnête si tu n'as pas de stock temps réel : une vraie offre limitée dans le temps (compte à rebours réel qui se termine), pas un badge figé.
Élevé 05

Image hero à alléger (élément LCP)

hero.jpeg pèse ~1,9 Mo en 2752×1321. C'est le principal frein à la vitesse mobile.
1 · Activer AVIF/WebP globalement
js 
// next.config.js
module.exports = {
  images: { formats: ["image/avif", "image/webp"] },
};
2 · Hero en next/image avec priority + sizes
jsx 
<Image
  src={"/hero.jpeg"}
  alt="CLINI WHITE Teeth Whitening"
  fill priority                 // LCP → préchargé, pas de lazy
  sizes="100vw"
  quality={72}
  style={{objectFit:"cover"}}
/>
// Résultat : le navigateur reçoit un AVIF ~120–180 Ko au lieu de 1,9 Mo
💡 Pourquoi : le hero est l'élément qui définit le Largest Contentful Paint. Le passer en AVIF responsive fait chuter le poids de ~90 % et améliore directement le score mobile et le SEO.
🖼️ Si tu n'utilises pas next/image pour le hero, sers un <picture> avec sources AVIF/WebP + srcset (480/768/1280/1920 px).
Élevé 06

Avis clients rédigés (preuve sociale réelle)

On voit une note (4,8/4,9) mais aucun avis texte. La preuve chiffrée seule convainc peu.
1 · Intégrer un vrai widget d'avis

Le plus simple et crédible : un outil dédié qui collecte et affiche des avis vérifiés (texte + photos) — Judge.me, Loox ou Okendo. Ils gèrent la collecte post-achat par email et le balisage Review automatiquement.

2 · Composant d'avis + schema Review (si tu gères en interne)
jsx 
function Reviews({ reviews }) {
  return (
    <section className="reviews">
      {reviews.map(r => (
        <article key={r.id} className="review">
          <div className="stars">{"★".repeat(r.rating)}</div>
          <strong>{r.author} <span className="verified">✓ Verified</span></strong>
          <p>{r.body}</p>
          {r.photo && <img src={r.photo} alt="Customer result" />}
        </article>
      ))}
    </section>
  );
}
💡 Pourquoi : des verbatims réels avec photos avant/après lèvent les objections mieux que n'importe quel argument marketing — surtout sur un produit « résultat visible ».
⚖️ N'affiche que de vrais avis. Un badge « Verified » sur de faux avis est un risque légal et de réputation.
Élevé 07

Cohérence des chiffres de preuve sociale

Home : « 4.8 par 5 600+ clients ». Fiche : « 4.9 · 767 avis ». Des chiffres qui varient sans logique affaiblissent la confiance.
Une source unique de vérité pour les stats de marque
js 
// lib/socialStats.js — LA référence unique, utilisée partout
export const BRAND_STATS = {
  avgRating: 4.8,          // note globale marque
  totalReviews: 5642,      // total tous produits
  totalCustomers: "5,600+",
  countries: "50+",
};
// La note PAR PRODUIT (ex : 4.9 / 767) reste locale au produit —
// mais la note GLOBALE affichée dans le hero vient toujours d'ici.
💡 Pourquoi : distingue clairement la note globale de marque (constante partout) de la note par produit (propre à chaque fiche). Deux chiffres différents pour la même chose = doute.
Moyen 08

Upsell quantité + abonnement (panier moyen)

La fiche ne propose que « Buy 1 ». Aucun palier de quantité ni abonnement : de l'AOV laissé sur la table.
Paliers de quantité avec remise progressive
jsx 
const tiers = [
  { qty:1, label:"Buy 1",           price:14.99 },
  { qty:2, label:"Buy 2 — Save 10%",  price:26.99, popular:true },
  { qty:3, label:"Buy 3 — Save 20%",  price:35.99 },
];

{tiers.map(t => (
  <label key={t.qty} className={`tier ${t.popular?"popular":""}`}>
    <input type="radio" name="qty" value={t.qty} />
    <span>{t.label}</span>
    <strong>{formatPrice(t.price)}</strong>
  </label>
))}
💡 Pourquoi : le blanchiment se consomme par cure/recharge. Des paliers « Achetez 2/3 » et une option abonnement augmentent le panier moyen et la valeur vie client, sans coût d'acquisition supplémentaire.
Moyen 09

Bandeau « garantie » répété 10×

Le marquee répète la même phrase 10 fois. Alterner plusieurs bénéfices est plus utile et moins lourd.
Faire défiler plusieurs messages plutôt qu'un seul
jsx 
const perks = [
  "100% Money-Back Guarantee",
  "Peroxide-Free Formula",
  "Free Shipping over £30",
  "Rated 4.8 by 5,600+ Customers",
  "Results in 7 Days",
];

<div className="marquee">
  {perks.map((p,i) => <span key={i}>{p} ✦ </span>)}
  {perks.map((p,i) => <span key={"b"+i} aria-hidden>{p} ✦ </span>)}
</div>
💡 Pourquoi : le même espace vend désormais 5 arguments au lieu d'un seul martelé. Plus informatif, moins répétitif.
Moyen 10

Barre de livraison gratuite

Aucune info livraison en haut de page. Les frais surprise au checkout sont une cause majeure d'abandon.
Barre dynamique « plus que X£ pour la livraison offerte »
jsx 
const FREE_SHIPPING = 30;

function ShippingBar({ cartTotal }) {
  const left = FREE_SHIPPING - cartTotal;
  return (
    <div className="ship-bar">
      {left > 0
        ? `Add ${formatPrice(left)} for FREE shipping 🚚`
        : "🎉 You've unlocked FREE shipping!"}
      <progress value={cartTotal} max={FREE_SHIPPING} />
    </div>
  );
}
💡 Pourquoi : annoncer le seuil dès la home rassure et pousse à ajouter un produit pour l'atteindre — ça augmente le panier tout en réduisant l'abandon.
Moyen 11

Scripts tiers (performance)

14 scripts chargés. Individuellement légers, ils peuvent cumuler du temps de blocage sur mobile.
Charger chaque tag avec la bonne stratégie next/script
jsx 
import Script from "next/script";

// Analytics : après l'hydratation, jamais bloquant
<Script src="/analytics.js" strategy="afterInteractive" />

// Chat, pixels marketing : au repos du navigateur
<Script src="/chat-widget.js" strategy="lazyOnload" />
💡 Pourquoi : afterInteractive et lazyOnload retirent les scripts non-critiques du chemin de rendu → meilleur TBT/INP sans rien perdre en fonctionnalité.
🔍 Audit rapide : liste tes 14 scripts, garde les essentiels, différe le reste, supprime les tags marketing inutilisés.
Moyen 12

robots.txt — retirer la directive « Host: »

« Host: » est une ancienne directive Yandex, ignorée par Google. Inutile et source de confusion.
robots.txt corrigé (à coller tel quel)
txt 
User-Agent: *
Allow: /
Disallow: /api/
Disallow: /account/
Disallow: /cart/
Disallow: /checkout/

Sitemap: https://cliniwhite.com/sitemap.xml
💡 Pourquoi : la canonicalisation d'hôte se gère par la redirection 301 (correctif 02) et la balise canonical, pas par « Host: ». On garde un robots.txt propre.
Moyen 13

Accessibilité (contraste, focus clavier)

Sous-titre du hero en gris clair (contraste à vérifier), états de focus à rendre visibles.
1 · Focus clavier visible sur tous les éléments interactifs
css 
/* Anneau de focus net, seulement au clavier */
:focus-visible{
  outline:3px solid #6b5bd2;
  outline-offset:2px;
  border-radius:4px;
}
2 · Contraste du texte (viser WCAG AA ≥ 4,5:1)
css 
/* ❌ gris trop clair sur fond clair */
.hero-subtitle{ color:#9a98ad; }
/* ✅ assez foncé pour être lisible partout */
.hero-subtitle{ color:#3a3852; }
💡 Pourquoi : l'accessibilité élargit ton audience, évite un risque légal, et Google en tient compte. Un focus visible et des contrastes suffisants sont des gains rapides.
🧪 Vérifie l'ensemble avec Lighthouse (onglet Accessibility) ou l'extension axe DevTools — vise un score ≥ 95.
